# 露丝 · 角色资产加工

网球游戏用的角色「露丝」，从一个 AI 生成的 50k 三角面 GLB 出发，做体检、清理、
分割、绑定，并给出重新生成时的姿势建议。

**一句话结论：这份模型的几何与贴图值得保留，已经修好材质、归一化尺度、绑好骨架并导出；
但它的 rest pose（手臂自然下垂）决定了它不能干净地掰成 A-Pose —— 如果要继续做动画，
建议按本文末尾的姿势重新生成一次。**

## 已做的修改

1. **焊接**：35,438 → 24,844 顶点。这一步是所有后续操作的前提 —— 不焊接时因为
   UV seam 和硬边法线，同一位置点被拆成多个，模型会被误判成 1,168 个碎片。
2. **尺度归一化**：1.1846 m → 1.65 m（手臂等比例放大，几何比例不变）。
3. **材质修复**（效果最直观，见 `16_final_*.png` 对比 `00_original_*.png`）：
   - `specularColorFactor` 2.0 → 1.0。原值越界，表现就是高光过曝、皮肤像塑料或上了油。
   - `blend_method` HASHED → OPAQUE。glb 里没有 `alphaMode`，本来就不透明，
     HASHED 只是白白开启透明排序。
4. **语义分割**：把模型分成身体/头发/马尾/遮阳帽/眼镜/Polo/裙/袜/鞋等区域，落成顶点组。
5. **Humanoid 骨架**：34 根骨，**Mixamo 命名**（Hips / Spine / LeftArm / LeftUpLeg …），
   便于以后把 Tennis-MoCap 的 BVH 直接 retarget。关节位置全部按实测放置
   （裆 0.77 / 膝 0.44 / 踝 0.11 / 肩 1.205 / 肘 0.97 / 腕 0.77，马尾 1.20–1.455），
   并用 BVH 射线求交逐根验证过骨骼是否落在网格内部。
6. **蒙皮权重**：语义分组 + 距离权重手工写，而不是用 Blender 自动权重（原因见下）。
7. **导出**：`ruth_bound.glb`。

## 没做成的事，以及证据

### A-Pose 掰不出来

原报告建议 P2「重新做 Rest Pose 成 A-Pose」。我试了 6 轮，**结论是这份几何做不到**：

根因是几何事实，不是算法不够好。自然下垂时：

- 手/前臂到**裙子侧面只有 2.2 cm**，而到裙骨 3.9 cm —— 距离更近的是手臂骨
- 手同时贴在大腿外侧同一高度

也就是说「手、裙子、大腿」三个部件的表面在原始几何里就是相互贴合的。把它们掰开必然撕裂，
判据只能决定撕哪一边。6 轮的演进正好演示了这一点：

| 轮次 | 判据 | 结果 |
|---|---|---|
| 1 | 顶点组排除裙子 | 手臂撕成扁片（因为颜色分类把自阴影误判成头发，把手臂锁给了 Head） |
| 2 | 修分类为「位置为主」 | 裙子出横向锯齿（裙子的藏青侧条属于 NAVY 组，不在排除列表） |
| 3 | 加「到手臂骨比到腿骨/躯干骨近」 | 裙子被扯出翼状突起 |
| 4 | 改「全局最近骨」 | 更糟（裙侧到前臂 2.2cm 比到裙骨还近） |
| 5 | 语义分组 + 最近骨双条件 | 仍出百叶窗式片状撕裂 |

### 但绑定本身是对的

最后我用不破坏几何的路线：**保留自然下垂的 rest pose**，权重用语义分组手工写。
诊断证实绑定质量正常：

```
上臂中  权重 LeftArm 0.908      位移 0.144 m
前臂中  权重 LeftForeArm 1.0    位移 0.670 m
手掌    权重 LeftHand 1.0       位移 0.949 m
非裙子顶点被分到裙骨 >20% 的数量：0
```

形变测试里唯一的问题是：**手臂上举 90° 时，腋下被拉出一片膜状几何**。
这不是权重错误（权重和骨骼位置都验证过），而是**腋下没有余量几何** ——
原始模型是按手臂下垂生成的，那里的表面不足以展开。这既是 A-Pose 的价值所在，
也是 retopo 在腋下加 edge loop 的价值所在。

## 重新生成时的建议

如果重新生成，以下几条能直接决定后面能不能顺利绑定。

### 1. 用 A-Pose（最重要）

```
        O
       /|\
     ／ | ＼        手臂离身体 40–45°
    /   |   \
```

- 手臂外张 **40–45°**，手肘微屈 10–15°
- **手肘到裙子留出 >5 cm 间隙**，不要出现"手臂贴着身体/裙子"的区域
- 双腿自然分开约肩宽，不要并拢
- 手指自然分开（这次的模型手指完整，保持住）

这一条能省掉整个「掰 A-Pose」步骤，也让自动权重和 retopo 都变干净。

### 2. BaseColor 里不要烘自阴影（第二重要）

这次的贴图把「手臂贴着身体」产生的自阴影烘进了 BaseColor，暗部亮度 <0.45。
后果：按颜色做语义分割时，**腋下、前臂、手被误判成头发**，我把它们锁给了 Head 骨，
手臂就撕成了扁片。

如果确实需要阴影，请**单独输出 AO 贴图**，BaseColor 保持固有色。

### 3. 部件用多个材质槽

现在是全身 1 个材质 + 1 张 4096 图集，所以只能靠颜色猜部件。
如果身体 / 上衣 / 裙 / 头发 / 鞋各占一个材质槽，就直接按材质分割，不用猜。

### 4. 其他

- 身高按 **1.65 m**（这次只有 1.185 m）
- 贴图 **2K 就够**：3 张 4096 让文件到 29 MB，对 WebGL 角色偏大
- 面数 **40–55k 完全可以**，不用压

### 5. 继续保持的优点

- **单一封闭流形表面**（焊接后 24,844 点、0 非流形边、0 边界边）—— 很难得，别破坏
- 手、脚、五官、马尾、帽檐都完整
- 左右基本对称

### 踩过的坑（都写在对应脚本的注释里）

- **glTF 导入的旋转不可信**：`rotation_mode` 是 `QUATERNION`，写 `rotation_euler` 无效；
  而且导入器有时给 Y-up→Z-up 旋转、有时不给。稳妥做法是先把对象变换烘进网格
  （`me.transform(ob.matrix_world)` + `matrix_basis = Identity`），再用
  「范围最大的轴就是身高轴」判断。
- **MCP 的 `execute_blender_code` 会序列化脚本的全局命名空间**，
  在全局留下 `NodeSocket` / `Node` 对象会让它在返回结果时抛
  `NodeSocketVector doesn't define __round__`。材质逻辑要收进函数。
- **`open_mainfile` 之后 `bpy.context` 变成受限 Context**（没有 `selected_objects`），
  后续 `mode_set` 全部失败。所以脚本要自包含、从源文件导入，而不是打开 .blend 起手。
- **`CorrectiveSmooth` 的 `rest_source` 不能用 `ORCO`**：ORCO 是导入时的原始坐标，
  网格经过焊接/缩放/轴变换后两者不对应，平滑修正会把网格拉成片状。要用 `BIND` 并显式 bind。
- **自动权重在这种「衣服和皮肤缝在同一张连续表面」的模型上会互相污染**，
  而且 `z >= 1.19` 这类纯高度阈值要小心：肩高就是 1.205，会把肩外侧顶点判进头部。
